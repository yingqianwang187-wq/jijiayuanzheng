## ① 世界观与玩法

### 1.1 世界观（设计文档 §1，已确认）
- 近未来都市，人类城市被失控的机械军团（暴走 AI）攻陷。
- 玩家身份：**指挥官**，率领机甲少女（机娘）小队**自动推关**，夺回被机械军团占领的家园。
- 基调：轻松搞笑；每章开头 2~3 句小对话（阶段 3 实装），MVP 不做剧情。

### 1.2 玩法（MVP = 阶段 0，设计文档 §9 + 手册 §2.3）
- **机娘**：小钰（近战·R）、阿岚（远程·R），MVP 仅"等级"成长（突破/升星留阶段 3）。
- **关卡**：第 1 章 5 关，每关 1 波敌人，自动战斗，**每秒结算一轮**。
- **挂机（点一下收获）**：金币不自动进账；按"距上次收获 / 上次打开的实际经过时长 × 每秒产出"累计成**待收获金币**（在线+离线均计入），点击一次性领取。
- **经济循环**：挂机收获 / 推关 → 金币 + 机娘经验 → 升级机娘（金币+经验双消耗）→ 推更远 → 首通钻石（阶段 1 起用）→ 抽卡 → 更强机娘 → 再推关。
- **存档**：本地存档（金币、待收获、机娘等级与经验、解锁关卡、首通记录）；**自动存档**（升级/通关即时、待收获金额与时间戳节流保存）；换设备/清浏览器会丢（MVP 接受）。
- **画面**：先用简单图形/头像代替立绘（后续换正式立绘）。
- **验收标准**（来自设计文档）：打开网页 → 看到机娘自动打关 → 挂机收获金币 → 升级机娘（金币+经验）→ 打过 5 关 → 刷新页面进度还在。

### 1.3 战斗规则（设计文档 §8.3 + 手册 §2.2，已确认）
- **每秒结算一轮**（节拍结算）：按速度排序先后出手 → 我方全体攻击一次 → 敌方全体攻击一次 → 结算血量 → 发信号。
- 胜负结果：**敌人全灭 = 胜利** → 首通发放金币奖励并解锁下一关，且发放该关机娘经验给**所有出战机娘（含本局阵亡者）**（**非首通重复胜利也给经验**，用于练级）；**我方全灭 = 失败** → 无经验、可重试当前关。
- **返回主界面 = 中止本局战斗**（`Game.stop_battle()`，可重进重打；战斗不会在后台继续）。
- 血量归零即退场；每关 1 波敌人。战斗规模按数组设计，支持后期扩展为我方**最多 5 名机娘上阵、敌方每波最多 5 名**（MVP：2 名机娘 vs 每关 1 名敌人）；技能/装备属后期阶段。
- 节拍间隔、伤害公式等具体数值属 Data（§3.3），契约只约定"怎么通知"，不约定"怎么算"。

### 1.4 货币（设计文档 §3，已确认）
| 货币 | 代码术语 | 获取 | 用途 | MVP 是否涉及 |
|---|---|---|---|---|
| 金币 | gold | 挂机产出、关卡首通 | 机娘升级等基础消耗 | ✅ 唯一涉及 |
| 钻石 | diamond | 首通、每日任务、充值 | 抽卡、加速挂机、买金币 | 阶段 1 |
| 付费币 | paid_coin | 仅充值 | 商城限时礼包等付费专属 | 阶段 4 |

## ③ 接口约定（重点）

### 3.1 数值唯一变更方 = Game
- 金币、机娘状态、敌人状态、关卡进度等一切**会变的数值**，只允许 Game 修改。
- Game 每次修改后，必须通过 Contract 上声明的信号通知（emit）。
- UI（main_ui / battle_view）**只 connect 信号来显示**，绝不自己改数值、绝不 emit 信号。
- 红线（代码评审必查）：
  - UI 脚本中不允许出现 `gold =`、`hp =` 之类的赋值；
  - UI 脚本中不允许出现 `emit_signal` / `.emit(`；
  - 一切显示值以信号参数为准，UI 不缓存、不推算。
- **首屏铺底例外**（v0.3 明确）：进入战斗 / 返回主界面等场景切换时，切换前发出的信号 UI 收不到，故允许 UI 在 `_ready()` 时对 Game 公开状态做**一次只读快照**用于首次显示；此后一切更新一律走信号。快照只读——仍禁止写数值、禁止 emit、禁止缓存后续值。

### 3.2 存档唯一负责方 = Save
- 只有 Save 知道存档文件路径与格式（`user://save.json`，FileAccess + JSON）；其他脚本不得直接读写存档文件。
- 公开接口：
  - `save_game()`：**无参数**，把当前状态写入存档；当前状态唯一持有者是 Game（§3.1），Save 经 `Game.get_save_snapshot()` 取**只读快照**后写档；
  - `load_game() -> Dictionary`：读档，**失败（缺失/损坏/版本不符）必须返回默认值并继续运行，不允许报错崩溃**；读档/默认值逻辑**不依赖 Game**。
- **自动存档时机**（由 Game 调用，契约约定）：
  - 升级成功、通关（level_cleared）后：**即时**调用 `Save.save_game()`；
  - 挂机待收获：**每 5 秒节流**存一次（待收获金额 + 时间戳；节流间隔属数值，由 B 放入 Data）。
  - 理由：保证任务 8 验收"刷新页面进度还在"可达成。
- 存档形状：`{gold, mechs{level, exp}, unlocked_level, first_cleared, idle_pending, idle_last_time}`；其中 `first_cleared` 记录已首通的关卡集合，防止重开后最后一关重复领取首通奖励；`mechs` 每名机娘含 **exp**（机娘经验）；`idle_pending` 为待收获金币、`idle_last_time` 为上次结算时间戳（支持离线累计）。
- 默认值内容：金币 0、机娘取 Data 中的初始配置（Lv1、经验 0）、解锁关卡 1、`first_cleared` 为空、`idle_pending` 为 0、`idle_last_time` 取当前时间（具体形状由 B 按契约实现）。

### 3.3 数据与常量存放（谁的东西放哪）
| 内容 | 唯一存放处 |
|---|---|
| 机娘 / 敌人 / 关卡数值表、节拍间隔等数值（设计文档 §8） | scripts/data.gd（Data） |
| 常量 / 信号 / 术语 / 自动加载名 | scripts/contract.gd（Contract） |
| 当前状态与规则逻辑（把 Data 的静态数值变成"当前值"） | scripts/game.gd（Game） |
| 显示逻辑（只 connect 信号） | scripts/main_ui.gd、scripts/battle_view.gd |

### 3.4 战斗 = 节拍结算
- 战斗节奏由 Game 掌控：每秒 1 轮，按速度排序结算我方一次攻击、敌方一次攻击，更新血量后发信号。
- battle_view 只做三件事：**连接信号 → 刷新血条 → 播放表现**；不做物理碰撞、不做位移运算、不自己扣血。
- 血条数值唯一来源：Game 发出的信号参数。

### 3.5 信号清单（全部声明在 scripts/contract.gd，只有 Game 允许 emit，UI 只 connect）
| 信号 | 参数 | 含义 | 谁 connect |
|---|---|---|---|
| gold_changed | value: int | 金币变化（挂机/首通/升级扣费后都会发） | main_ui |
| mech_girl_updated | id: StringName, hp: int, atk: int, level: int | 机娘状态变化（升级/战斗后；**战斗外 hp 为满血**：战斗血量是战斗局部概念、不持久化） | main_ui / battle_view |
| enemy_updated | id: StringName, hp: int | 敌人血量变化（刷新血条） | battle_view |
| battle_tick | tick: int | 战斗节拍（每秒 1 轮） | battle_view |
| level_cleared | level: int, first_clear: bool | 关卡通过（含是否首通，首通发首通奖励） | main_ui |
| battle_failed | level: int | 战斗失败（我方全灭；UI 显示失败/重试） | battle_view |
| level_progress_changed | level: int | 当前关卡变化（解锁下一关） | main_ui |
| idle_rewards_updated | amount: int | 待收获金币变化（挂机累计，含离线；点击收获后发 0） | main_ui |
| mech_exp_updated | id: StringName, exp: int, exp_next: int | 机娘经验变化（胜利得经验 / 升级消耗后） | main_ui |

### 3.6 调用入口（与信号方向相反：UI → Game / Save）
> 通道规则：**一切调用走本表入口，一切状态回发走 §3.5 信号**；调用后不直接依赖返回值，状态一律以信号为准。

| 方向 | 入口 | 说明 |
|---|---|---|
| UI → Game | Game.start_battle(level: int) | 进入关卡，开始自动节拍战斗 |
| UI → Game | Game.upgrade(mech_id: StringName) | 升级机娘：**扣金币 + 机娘经验** → 升等级 → 提攻血 → 发信号 |
| UI → Game | Game.collect_idle() | 领取待收获金币：入账后发 gold_changed + idle_rewards_updated(0) |
| UI → Game | Game.stop_battle() | 中止当前战斗（返回主界面时先调用；可重进重打） |
| UI → Game | Game.upgrade_cost(mech_id: StringName) -> int | 只读：升下一级所需金币（UI 显示/禁用判断用） |
| UI → Game | Game.upgrade_exp_cost(mech_id: StringName) -> int | 只读：升下一级所需经验（同上） |
| UI → Save | Save.save_game() | 立即写档（手动存档按钮） |
| Game → Save | Save.save_game() | **自动存档**：升级成功、通关后即时；待收获金额与时间戳每 5 秒节流一次 |
| Save → Game | Game.get_save_snapshot() | 只读快照：`save_game()` 无参数，写档数据经此获取（不修改数值） |
| Game → Save | Save.load_game() | 启动时读档；失败返回默认值 |

## 变更记录

### v0.5（本次，依据总指挥 A 裁决——D 首轮只读验收）
1. **返回 = 中止本局战斗**（§1.3 / §3.6）：新增入口 `Game.stop_battle()`，battle_view 返回按钮先中止再切场景；战斗不会在后台继续。
2. **阵亡机娘也得经验**（§1.3 澄清）：战斗胜利时所有出战机娘（**含本局阵亡者**）获得该关经验；MVP 从简不惩罚，后期 5v5 再考虑策略性。
3. **升级费用可读**（§3.6）：新增只读入口 `Game.upgrade_cost(id)` / `Game.upgrade_exp_cost(id)`，供 UI 显示/禁用判断，消除"UI 自行换算费用"的观察项。
4. **主界面"上次通关奖励"消息**（§3.6 快照）：Game 记录内存态 `last_clear`（不入档），重入主界面时由 UI 快照显示。

### v0.4（依据总指挥 A 裁决——首轮试玩 4 条体验问题）
1. **挂机改为"点一下收获"**（§1.2 / §3.2 / §3.5 / §3.6）：金币不自动进账；按实际经过时长（在线+离线）累计待收获金币，点击一次性领取。新增信号 `idle_rewards_updated(amount)` 与入口 `Game.collect_idle()`；存档形状新增 `idle_pending` / `idle_last_time`。
